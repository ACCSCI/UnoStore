# UnoStore — 项目目标与验收标准

> 文档状态：定稿于 2026-07-31 设计讨论。所有规则、里程碑、验收标准以本文档为准。

## 1. 项目愿景

**Uno × 炉石传说混合卡牌对战游戏**：保留 Uno 的「先出完手牌获胜」核心，引入炉石式的水晶资源与卡牌效果，形成独特的「双卡流」策略深度。精美 3D 卡通风演出 + 章节式单人剧情 + 8 人联机对战。

## 2. 玩法定稿

### 2.1 双卡流核心

- **每回合开始**：抽 1 张 Uno 牌（公共牌堆）+ 1 张炉石牌（私人牌组）
- **行动结构**：本回合可打 **1 张 Uno 牌** + **任意张炉石牌**
- **水晶经济**：Uno 数字牌打出时，其点数产出水晶，水晶**冻结一回合**（冻结无上限），下回合叠加解冻后可用于打出炉石牌
- **Nomercy 变体**：存在「全员跳过」类牌，打出后其他所有玩家跳过一回合，打出者获得额外行动（可再打 1 张 Uno 牌）
- **暂停类效果不打断炉石出牌**：打出暂停/反转/跳过牌后，本回合仍可继续打炉石牌

### 2.2 手牌与牌组

- **初始手牌**：每人 7 张 Uno + 3 张炉石
- **Uno 牌**：公共牌堆（标准 76 张数字牌 + 功能牌）；每回合抽 1；打不出牌时**抽 1 张即止**（+2/+4 惩罚叠加照常）
- **炉石牌**：私人牌组；V1 使用预设牌组（若干套不同风格），**架构预留牌组编辑器**
- **UNO 报牌**：**自动报牌** —— 系统自动检测玩家剩 1 张手牌时提示「UNO」，未报牌打出最后一张则罚抽 4

### 2.3 胜负

- **先出完 Uno 手牌者获胜**（标准 Uno 快感）
- 炉石牌是辅助手段：可清对手手牌、加速自身出牌、干扰对手节奏

### 2.4 可扩展性（硬性要求）

规则引擎必须以**数据 + effect 注册表**方式设计：新卡牌 = 新数据 + 新 effect 函数，无需改动核心状态机。后续持续更新（新卡牌、新机制、新 Boss）必须只做增量添加。

## 3. 里程碑与验收标准

### Phase 0 — 工程基础设施 ✅ 已完成

| 要素 | 验收标准 | 状态 |
|---|---|---|
| VCS | git 仓库（main 分支），提交历史清晰 | ✅ |

### Phase 1 — 规则引擎（纯 TS 状态机，无渲染）

**验收标准**：
- [ ] Uno 数字牌堆 76 张 + 功能牌（跳过/反转/+2/+4/Wild）完整实现
- [ ] 炉石牌卡池（≥ 12 张不同效果）+ 至少 2 套预设牌组
- [ ] 完整对局流程：发牌 → 回合 → 出 Uno 牌 → 水晶冻结/解冻 → 打炉石牌 → 回合结束
- [ ] 水晶冻结一回合、下回合叠加解冻可用
- [ ] 暂停类牌不打断本回合炉石出牌
- [ ] Nomercy「全员跳过」牌实现（额外行动）
- [ ] 自动 UNO 报牌（剩 1 张提示，未报罚抽 4）
- [ ] +2/+4 惩罚叠加、打不出抽 1 即止
- [ ] 出完 Uno 手牌获胜判定
- [ ] effect 注册表架构：新增卡牌效果零改动核心状态机
- [ ] 每个规则路径有单元测试覆盖（≥ 80% 关键路径）
- [ ] 单文件 ≤ 600 行

### Phase 1.5 — 文字化对战验证

**验收标准**：
- [ ] CLI 脚本 `bun run replay` 可执行完整文字化对局

- [ ] 支持逐步操作（出牌/打炉石牌/结束回合；无牌可出时自动抽 1 张）
- [ ] **人工走查**：与用户一起走 3 局完整对局，确认规则逻辑正确
- [ ] 发现的问题全部修复后进入 Phase 2

## 4. 全局工程约束（所有阶段生效）

1. **单文件 ≤ 600 行** —— 超限拆分，不得例外
2. **纯逻辑与渲染分离** —— 规则引擎（src/game）零 DOM/Three.js 依赖；渲染层（src/ui）零规则逻辑
3. **effect 注册表** —— 新卡牌效果只增量注册，不改核心状态机
4. **全量质量门** —— 提交前 biome check + typecheck + test 全过（Lefthook 强制）
5. **可测试** —— 核心规则路径必须有单元测试
6. **VibeHub 红线**（多人阶段）—— 不自建后端/数据库/WebSocket；实时状态走 P2P 不落库；Canvas + rAF 渲染
