## 5. 发现的问题（按严重程度）

### 🔴 致命

**P1. 手牌在俯视视角下视觉上堆叠成一团，玩家无法辨认牌面（数字/颜色）**
- 现象：三张战斗截图（4s 与 8s）均一致——手牌挤压在底部，只能看到牌背轮廓，完全无法读取牌的内容，玩家难以做打牌决策。
- 原因分析（对照 `src/ui/scene/HandRenderer.ts`）：扇形总角度 `FAN_ANGLE = 0.8` 弧度（约 46°）、半径 4.1，7 张以上的牌挤在约 3.2 单位宽的弧上；卡牌平放且仅微倾（`rotation.x = -0.35`），相机在 `(0, 5.5, 7.5)` 高处俯视（`GameView.ts`），相邻牌几乎贴在一起，俯视时互相遮挡。
- 建议：
  - 加大扇形展开角（如 `FAN_ANGLE` 提到 1.8–2.2 弧度）并让牌面朝向相机（沿 x 轴旋转约 -1.2 左右"立起来"）；
  - 降低相机俯角或前移，使扇形平面更接近视线；
  - 悬停（hover）时抬升 + 放大 + 前移做分离高亮（已有 hover 逻辑，可加放大/前移）。

### 🟠 严重

**P2. 「结束回合」按钮被手牌遮挡、「抽牌」按钮被座位标记遮挡**
- 现象：按钮与手牌同处底部区域互相交叠；「抽牌」按钮还被橙色座位标记（玩家位置椭圆）压住约一半。
- 建议：将 3D 按钮上移或移出座位标记范围；收紧手牌扇形占用宽度（与 P1 一并解决）；给按钮更高优先级的叠放（渲染顺序/高度差），确保任何时刻不被卡牌或标记压住。

**P3. 桌面中央的弃牌堆顶牌与状态栏「顶牌 黄 4」视觉对应不直观**
- 现象：状态栏明确显示顶牌为「黄 4」，但 mmx 两次识别桌面顶牌为黑色/深色卡，玩家在桌面上很难一眼确认顶牌颜色数字。
- 备注：`TableCenter.ts` 中弃牌堆顶牌是朝上可见的正面，但小尺寸（0.55×0.72 单位）+ 俯视角度使其难以辨认；若实际渲染为纯色黑（万能牌底色 `#222`）则与状态栏信息可能不同步，需要人工在可视环境确认。
- 建议：放大弃牌堆顶牌尺寸/抬高离桌高度，或将顶牌信息直接以 UI 大号元素（当前已有状态栏文字）强化；检查顶牌面纹理加载是否正常。

### 🟡 中等

**P4. 锁定章节卡片整体透明度 0.5，标题文字对比度不足**
- 现象：二/三/四章卡片整卡半透明，标题和描述文字在深色背景上变淡（`style.css` `.chapter-card.locked`）。
- 建议：保持锁定感但仅对装饰层降透明度，标题/描述保持可读对比度（如 opacity 0.7+），或用 🔒 图标替代整体降透明度。

**P5. 「💎 可用 0」与「🎯 行动 1」语义对玩家不直观**
- 现象：回合开始显示「可用 0 / 行动 1」，手里却有多张牌，玩家易误读为"无牌可打"。经代码核实 `可用 = p.free`（水晶/行动资源，`BattleScreen.ts`），并非可打出牌数，属 UI 语义问题而非数据 bug。
- 建议：为「可用」「行动」加图标/悬浮说明，或改文案（如「💎 水晶 0」），避免与手牌数量混淆。

### 🟢 轻微

**P6. `/favicon.ico` 404 ×2**
- 现象：浏览器自动请求 favicon 返回 404，产生 2 条 console error。
- 建议：在 `public/` 添加 favicon.ico（或 index.html 加 `<link rel="icon">`）。

**P7. 主菜单副标题「双流卡牌对战」对比度偏低**
- 现象：浅灰小字在深紫背景上可读性一般。
- 建议：提亮文字颜色或加深色投影。

**P8. 彩色圆球/圆柱（座位标记）含义不明**
- 现象：桌面周围一排彩色球体/柱体，玩家不明确其含义（实为座位标记），且其中一个遮挡「抽牌」按钮。
- 建议：为座位标记增加说明或弱化显示；确保不与交互控件重叠。

## 6. 结论

- 流程可玩：主菜单 → 章节选择 → 对战全部可正常进入，按钮点击、页面跳转无故障，3D 场景成功加载，**无 WebGL/THREE 报错**。
- 最重要问题：**手牌视觉堆叠（P1）**——这是当前体验的核心缺陷，直接影响对局可操作性；其次为按钮被遮挡（P2）。
- 控制台层面仅有一个轻量 404（favicon），无功能性报错。
